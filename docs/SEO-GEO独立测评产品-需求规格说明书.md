# SEO/GEO 独立测评产品 — 需求规格说明书

版本：v1.0（MVP实现基线）
文档状态：已实现，用于种子客户验证

---

## 1. 产品概述

### 1.1 定位
面向已经付费购买SEO/GEO服务、但无法判断服务效果的企业，提供**不参与优化执行的独立第三方测评**，验证服务商的实际效果与合同承诺是否相符。

### 1.2 核心价值主张
- 客观：数据来自第三方独立工具（5118、爱站网、Ahrefs）和自建多模型查询引擎，不依赖服务商自报数据
- 独立：不承接SEO/GEO优化执行业务，避免"既当裁判又当运动员"
- 可复现：测评方法论固定，每期结果可横向对比

### 1.3 目标客户
已签署SEO/GEO服务合同、对效果存疑的企业市场负责人/决策者。不面向SEO/GEO服务商本身（避免利益冲突，见9.3）。

---

## 2. 核心功能模块

### 2.1 SEO数据接入模块
- 对接第三方SEO数据源（5118 / 爱站网 API，或Ahrefs/Semrush导出数据）
- 采集范围：关键词排名、自然流量趋势、外链数量与质量、技术健康度评分
- 数据周期：按月/按季度采集，形成时间序列

### 2.2 GEO检测模块（自建，核心差异化能力）
- **问题库构建**：按用户意图分层（认知期/比较期/决策期），每类不少于10条真实口语化问法，覆盖目标客户所在行业
- **多模型查询引擎**：批量投递至DeepSeek、豆包、通义千问、腾讯元宝等主流平台，可扩展
- **结果解析**：识别品牌是否被提及、提及位置、提及准确性、竞品对比排序
- **方法论固定化**：问题库和判定标准版本化管理，保证跨期可比、可复现、可自证

### 2.3 报告生成模块
- 结构化报告模板（见第3节）
- 数据自动填充 + 人工复核结论（早期MVP阶段以人工复核为主，避免自动化结论出错）

### 2.4 订阅监测模块
- 定期（月度/季度）自动重跑SEO+GEO检测
- 跨期趋势对比（本期 vs 上期 vs 合同目标）
- 异常预警（如某项指标环比大幅下滑）

### 2.5 客户管理后台（轻量级）
- 客户基本信息、服务商合同承诺值录入
- 历次报告归档、订阅状态管理

## 3. 报告内容规格

对应示例文件《SEO-GEO测评报告示例.docx》，标准报告包含：

| 章节 | 内容 | 数据来源 |
|---|---|---|
| 执行摘要 | 面向决策者的一页结论，含核心发现和达成率 | 汇总生成 |
| 测评说明 | 测评范围、方法论、独立性声明 | 固定模板 |
| SEO现状测评 | 核心指标 vs 合同承诺 vs 实际值对比表 | 5118/爱站网/Ahrefs |
| GEO现状测评 | 各AI平台品牌提及率 vs 竞品对比表 | 自建查询引擎 |
| 综合结论与建议 | 差距原因、下一步行动建议 | 人工分析 |
| 附录：方法论摘要 | 问题库构建原则，保证可自证、可复现 | 固定模板 |

**设计原则**：报告结论必须围绕"服务商承诺 vs 实际数据"对比展开，不做泛泛的效果评价；所有数据须标注来源，不使用测评方自己无法验证的数据。

## 4. 订阅制内容规格

一次性报告解决"当下怎么样"，订阅制解决"持续花的钱到底值不值"，具体包含：

### 4.1 定期测评报告
- 按月或按季度重新执行第2节的检测流程，生成新一期报告

### 4.2 趋势对比看板
- 核心指标的历史走势（而非单期快照），让客户看到服务商是在持续改善还是原地踏步
- 达成率变化趋势，直观呈现"这几个月投入有没有换来进展"

### 4.3 竞品动态追踪
- 持续跟踪2-3家同类竞品的GEO表现，判断品牌是在拉近差距还是被进一步甩开

### 4.4 异常预警
- 当某项关键指标环比下滑超过设定阈值时主动提醒客户，而不是等到下一期报告才发现

### 4.5 季度复盘会（人工服务，非自动化）
- 每季度一次，由测评方与客户过一遍数据变化，解读原因、讨论是否需要找服务商核实或调整策略
- 这一项是订阅制区别于"自动生成报表工具"的关键——把数据变成客户能直接用来跟服务商谈判的依据

## 6. 非功能需求

- **方法论一致性**：GEO问题库和判定标准一旦定版，同一客户跨期测评必须使用同一版本，变更需记录版本号，保证可比性
- **可自证性**：所有结论需可追溯到具体数据来源和计算逻辑，应对服务商可能提出的方法论质疑
- **保密性**：客户的合同信息、测评数据视为机密，不同客户数据严格隔离
- **早期不追求自动化程度**：MVP阶段报告生成允许大量人工介入，先验证客户是否认可这套方法论和结论，再决定automation投入优先级

## 8. MVP阶段计划

1. **第一期（人工跑通）**：用种子客户真实数据，人工完成一份完整报告，验证报告结构和结论是否被客户认可
2. **第二期（半自动化）**：把GEO查询脚本和报告模板固化，SEO数据接入用API自动拉取，人工负责结论撰写和复核
3. **第三期（订阅打磨）**：基于第一个订阅客户的实际使用反馈，确定趋势看板和预警阈值的具体形式
4. **第四期（复制验证）**：用固化后的方法论和模板，服务第二、第三家客户，验证是否能快速复制而不需要从零定制

## 9. 风险与注意事项

### 9.1 方法论质疑风险
若报告结论对服务商不利，服务商可能质疑测评方法。需保证问题库、判定标准全程留痕、可复现。

### 9.2 客户使用顾虑
客户可能因与服务商关系微妙而不敢直接使用不利结论去交涉。报告应附带"下一步行动建议"，而非仅指出问题。

### 9.3 客户与服务商角色隔离
不同时向SEO/GEO服务商销售"效果背书"类服务，避免独立性受质疑，损害品牌信任基础。

## 10. 待验证的关键假设（种子客户验证清单）

- [ ] 客户是否愿意为一次性报告付费，愿意付多少
- [ ] 客户是否愿意转为订阅制，主要顾虑是什么
- [ ] 报告结论是否真的被客户用来与服务商交涉，交涉结果如何
- [ ] GEO测评的问题库是否需要针对不同行业定制，还是能用同一套框架

## 11. 用户角色与业务边界

### 11.1 MVP用户角色

MVP采用单组织内部工作台，仅设置“测评人员”角色。测评人员可管理客户、项目、合同指标、SEO/GEO数据和报告。

客户门户、细粒度权限、支付与服务商账号不属于MVP。正式多租户上线前，须增加组织级数据隔离和身份认证。

### 11.2 独立性边界

- 平台只记录、核验和解释效果，不承接SEO/GEO优化执行；
- 自动识别结果只作为初判，最终准确性和合同达成判断由测评人员确认；
- 缺少证据的指标标记为“无法判断”，不得推定已完成；
- 报告必须显示数据来源、采样日期、问题库版本和人工复核状态。

## 12. 功能需求明细与验收标准

### FR-01 客户管理

**功能**

- 新建、查看和修改客户；
- 保存企业名称、品牌名、域名、行业和联系人；
- 一个客户可拥有多个独立测评或订阅项目。

**验收**

- 新建客户后可立即创建项目；
- 项目列表显示客户、品牌、域名和订阅状态；
- 不存在的客户或项目返回明确的404响应。

### FR-02 测评项目与订阅

**功能**

- 保存服务商、测评周期、监测频率、订阅状态、预警阈值和项目状态；
- 项目总览展示承诺达成率、SEO趋势、GEO提及率和异常提醒。

**验收**

- 支持月度和季度项目；
- 至少两期数据存在时显示上期对比；
- 指标下降超过项目阈值时生成异常提示。

### FR-03 合同承诺核验

**功能**

- 逐条保存合同原文、指标、比较符、目标值、实际值、证据和备注；
- 判断状态包括待核验、已达成、部分达成、未达成、无法判断。

**验收**

- 报告中的合同对照表与后台记录一致；
- 只有已完成判断的指标进入达成率分母；
- 无证据数据不能自动标记为已达成。

### FR-04 SEO数据

**功能**

- 手工录入关键词排名和聚合指标；
- 导入CSV，兼容中英文列名；
- 保存采样日期、来源、搜索引擎、关键词分类、排名、搜索量和目标页面；
- 保存流量、外链、技术健康度等时间序列指标。

**CSV最低字段**

- 排名数据：`keyword/关键词`、`position/排名`；
- 可选字段：`search_volume/搜索量`、`engine/搜索引擎`、`category/类型`、`captured_at/日期`、`source/数据源`；
- 指标数据：`metric_key/指标编码`、`metric_name/指标`、`value/数值`。

**验收**

- 成功导入行数和拒绝行原因可见；
- 不同日期的数据不互相覆盖；
- 趋势计算使用相同指标编码的相邻两期值。

### FR-05 GEO问题库

**功能**

- 问题库按项目和版本管理；
- 问题包含认知期、比较期、决策期意图、权重及预期事实；
- 同一项目的版本号不可重复。

**验收**

- 历史检测批次持续关联原问题库版本；
- 新版本不会覆盖旧问题和旧回答；
- 界面显示每个版本的问题数量和状态。

### FR-06 GEO检测与人工复核

**功能**

- 支持人工录入DeepSeek、豆包、通义千问、腾讯元宝等平台的完整原始回答；
- 支持OpenRouter和百度千帆批量接口，模型ID由执行人员配置；
- 自动初判品牌提及、文本位置、竞品提及和官网引用；
- 人工复核准确性、推荐状态、错误信息、竞品列表和备注；
- 单个数据源失败不丢失成功结果。

**验收**

- 每条回答可追溯到问题、问题库版本、批次、平台和模型；
- 未配置密钥时返回可审计的失败原因，不伪造结果；
- 自动初判可以被人工修正，报告准确率只使用已复核记录；
- 原始回答始终保留。

### FR-07 报告生成

**功能**

- 生成浏览器可打印的A4 HTML报告；
- 报告包含封面、执行摘要、测评范围、使用工具与数据来源、计算口径、合同核验、SEO、GEO、竞品、结论建议和方法论附录；
- 工具清单必须列出实际使用的SEO工具、分析数据源、AI平台、模型及采样日期；
- SEO部分展示聚合指标时间序列和关键词排名明细，不只展示单一总分；
- GEO部分展示问题库版本、采样条件、逐问题逐平台判定、模型、提及位置、准确性、竞品和复核状态；
- 附录保留GEO完整原始回答、错误信息和人工复核备注，形成可追溯证据链；
- 自动填充结构化数据，允许人工录入执行摘要、结论和建议；
- 报告可保存为固定归档版本。

**验收**

- 实时预览反映当前数据；
- 归档版本保存报告周期、结论和状态；
- 浏览器打印可输出PDF；
- 报告中的空数据明确显示“尚未录入/待复核”，不得生成虚假结论。
- 报告所列工具、模型、来源和原始回答必须与数据库记录一致。

### FR-08 趋势与异常预警

**功能**

- SEO指标比较最新两期；
- GEO品牌提及率比较最新两次批次；
- 汇总各平台提及率、准确率和竞品提及率；
- 按项目阈值生成下降预警。

**验收**

- SEO相对变化按 `(本期-上期)/|上期|` 计算；
- GEO变化使用百分点差；
- 无上期数据时显示“无上期对比”，不输出涨跌结论。

### FR-09 演示与调试

**功能**

- 一键生成完整演示客户、合同、SEO、GEO和报告数据；
- 保留原始 `/collect`、`/analyze` 接口和采集调试台；
- 提供OpenAPI文档。

**验收**

- 全新数据库点击“载入演示”后可以查看全部模块；
- 重复载入演示不会重复创建数据；
- `/api/health` 返回服务与数据库状态。

## 13. 数据模型

| 数据表 | 说明 |
|---|---|
| `clients` | 客户企业与品牌 |
| `projects` | 测评/订阅项目 |
| `competitors` | 项目竞品 |
| `commitments` | 服务商合同承诺、实际值及判断 |
| `keyword_targets` | 固定目标关键词 |
| `seo_metrics` | SEO聚合指标时间序列 |
| `keyword_rankings` | 关键词排名快照 |
| `geo_question_sets` | GEO问题库版本 |
| `geo_questions` | 标准化问题 |
| `geo_runs` | 一次检测批次 |
| `geo_responses` | 原始回答、自动初判和人工复核 |
| `reports` | 报告归档版本 |

所有项目级数据通过`project_id`关联；删除客户时由数据库外键级联清理其项目数据。MVP使用SQLite，正式多租户部署时迁移至PostgreSQL。

## 16. 测试与发布验收

MVP发布前必须通过：

1. 分析引擎、数据采集层和API全部单元测试；
2. 全新数据库初始化；
3. 演示数据幂等创建；
4. 客户→项目→承诺→SEO导入→问题库→检测批次→回答复核→报告的端到端流程；
5. 无密钥批量执行返回明确失败；
6. 首页、各业务页和报告页在桌面浏览器无阻断性错误；
7. 打印报告不包含后台按钮和导航。

## 17. MVP之后的明确扩展项
